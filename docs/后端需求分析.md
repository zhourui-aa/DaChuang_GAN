## 1. 工程形态

Maven 多模块 Monorepo，7 个 Java 服务（6 业务 + 1 网关）+ 1 个 Python AI 服务：

```
integrity-gateway     8080  路由/JWT/限流/20MB 限制
integrity-auth        8001  四级权限/JWT 签发/脱敏/审计
integrity-assignment  8002  课程·作业·班级·提交；docx/pdf/txt 解析→纯文本→MinIO+指纹
integrity-detect      8003  检测任务编排·状态机·MCP 调用·降级兜底·配置版本绑定
integrity-evidence    8004  特征/证据落库·ES 同步·相似案例检索
integrity-report      8005  报告组装·PDF/Excel 导出·看板聚合
integrity-appeal      8006  申诉工单状态机·复核记录·阈值反馈回写
integrity-ai-detector (Py)  LangGraph 多特征检测 + MCP Server
```

四条架构决策：**检测与业务解耦**（算法只在 Python）/ **特征与证据分离存储**
（特征进 MySQL、全文与证据进 ES、原文进 MinIO）/ **检测可降级**（模型不可用时纯统计特征）/
**结论可回归**（记录模型+配置版本，留出集跑回归）。

## 2. 数据模型：14 张表（手册 §3，DDL 已冻结 v1）

| 组 | 表 |
|---|---|
| 课程与提交 | `courses` `classes` `students` `assignments` `submissions` |
| 检测 | `detect_configs` `detect_tasks` `detect_features` `detect_evidence` `detect_results` |
| 申诉 | `appeals` `appeal_reviews` |
| 治理 | `datasets` `audit_logs` |

关键字段（决定后端接口契约）：
- `submissions.raw_text`（去噪后纯文本）· `text_sha256`（查重/缓存去重）
- `detect_features`：`feature_code` / `feature_value`（原始值）/ `feature_score`（归一化 0-1）/ `weight` / `feature_text`（中性描述）/ `source`（STATS|LLM）
- `detect_evidence`：`begin_pos` / `end_pos` / `snippet` / `reason` ← **可溯源的核心**
- `detect_results`：`risk_score` / `risk_level`(低/中/高关注) / `confidence` / `summary` / `review_suggestion` / `config_version`

### 检测特征 DSL v1（`detect_configs.feature_dsl`）
主特征 3 + 辅证 3，权重和 = 1，`risk_score = Σ(feature_score × weight)`：

| code | 名称 | 方向 | 权重 |
|---|---|---|---|
| PERPLEXITY | 文本困惑度 | inverse | 0.25 |
| PARAPHRASE_TRACE | 改写痕迹 | direct | 0.25 |
| WRITING_TRAJECTORY | 行文轨迹 | direct | 0.20 |
| BURSTINESS | 句长突发度 | inverse | 0.12 |
| LEXICAL_DIVERSITY | 词汇丰富度 | inverse | 0.10 |
| STRUCT_PATTERN | 结构规律性 | direct | 0.08 |

`min_chars = 200`：不足则不计综合分，只出特征明细并标注「短文本证据不足」。

## 3. 后端接口清单（手册 §4.2 + 扩展）

**assignment**
- `POST /api/assignment/submit` 单文件提交（file, assignmentId, studentId）
- `POST /api/assignment/submit-batch` 整班批量（≤200 文件）
- `GET  /api/assignment/list` 作业列表（含检测状态 / 关注等级 / 是否申诉中）

**detect**
- `POST /api/detect/run` 单条检测
- `POST /api/detect/run-batch` 整班异步（XXL-JOB 分片，返回批次号）
- `GET  /api/detect/result/{submissionId}` 状态与结果摘要（工作台轮询）
- `POST /api/detect/replay` 按配置版本回放历史样本

**evidence**
- `GET  /api/evidence/{submissionId}` 特征明细 + 每条件据的原文区间
- `POST /api/evidence/similar` 相似案例检索（ES more_like_this，不参与评分）

**appeal**
- `POST /api/appeal/create` 发起（高关注自动建草稿工单）
- `POST /api/appeal/review` 复核（结论 + 说明 + 是否标记「阈值需调整」）
- `GET  /api/appeal/list` 工单列表

**还需补**（手册只给了部分，后端要补全）：`report`（组装/导出/看板）、`auth`（登录/权限/脱敏/审计）、
`config`（detect_configs 的增改查/冻结）、`dashboard`（统计聚合）。

## 4. 异步与中间件约定

**RocketMQ Topic**
| Topic | Tag | 生产 → 消费 | 用途 |
|---|---|---|---|
| integrity-submit | SUBMITTED | assignment → detect | 解析完成触发检测 |
| integrity-detect | TASK_DONE | detect → report,evidence | 生成报告 + ES 同步 |
| integrity-detect | TASK_DEGRADED | detect → report | 降级，报告标注「仅统计特征」 |
| integrity-flag | HIGH_RISK | detect → appeal | 高关注自动建申诉草稿 |
| integrity-appeal | APPEAL_REVIEWED | appeal → detect,report | 阈值反馈入迭代候选池 |
| integrity-dead-letter | — | 所有 | 失败 3 次进死信，XXL-JOB 补偿 |

**Redis Key**：`detect:task:{taskId}:status` / `detect:result:{submissionId}` /
`detect:evidence:{submissionId}` / `detect:model:health`（决定降级）/ `detect:dup:{sha256}` /
`auth:session:{token}` / `ratelimit:{api}:{userId}`

**ES 索引 `submission_detect`**：content(ik_max_word) + features(nested) + risk_score/level +
config_version + appeal_status 等；用途 = 看板聚合 + more_like_this 相似检索。

**MinIO Bucket**：`submission-files` / `detect-reports` / `evidence-samples` / `dataset-samples`

## 5. Java ↔ Python 契约（MCP，手册 §6.3 / §7）

Java `integrity-detect` = MCP Client；Python `integrity-ai-detector` = MCP Server。

| 工具 | 入参 | 出参 |
|---|---|---|
| `detect_text` | submission_id, text, config_version | features[], evidences[], risk_score, risk_level, confidence, summary, suggestion, degraded |
| `explain_feature` | feature_code, feature_value, snippets[] | feature_text, reason |
| `recommend_review` | submission_id, features[] | suggestion, policy_refs[] |
| `search_similar_cases` | text, top_k | cases[] |

超时/降级：`detect_text` 30s(长)/15s(短) → 超时切纯统计特征模式 `degraded=1`；
`explain_feature` 8s → 模板渲染；`recommend_review` 8s → 固定文案；`search_similar_cases` 5s → 走 ES。
契约冻结后只允许**末尾追加可选字段**；Java DTO `@JsonIgnoreProperties(ignoreUnknown=true)`。

**AI 侧流水线（LangGraph）**：preprocess → extract_stats → agent_analyze → retrieve_cases →
aggregate → guardrail_check。降级分支：跳过 `agent_analyze`/`retrieve_cases`。

**护栏（Guardrails）**：禁定性词（作弊/抄袭/代写/造假/认定）/ 证据必可溯源 / 必含「仅供参考」声明 /
低置信度不得判高关注 / 文本只送本地模型。

**Agent Eval 口径**：留出集 200（人写 100 / AI 100）—— 召回 ≥0.85 / 误报 ≤0.10 / 证据命中 ≥0.95 / 护栏通过 =1.00。

## 8. 建议的实施分期（供选择）

**P0 · 端到端闭环可演示**（先跑通，不追全量）
- 服务：gateway + auth + assignment + detect + evidence + report + appeal（可先按模块化单体跑，接口边界与微服务一致，便于后拆）
- 存储：MySQL + Redis（+ MinIO 可选）
- 消息：先用 Spring 事件 / 线程池替代 RocketMQ
- AI：MCP 契约先落地，实现 **纯统计特征**（突发度/词汇丰富度/结构规律性/困惑度近似）+ 甲（句间语义平滑度）；LLM 走 Mock 或后置
- 前端：教师端 4 页 + （视裁决）学生端

**P1 · AI 与检索增强**
- 本地 LLM（Ollama Qwen2.5-7B）+ LangGraph + Guardrails + Agent Eval
- ES 8（看板聚合 + more_like_this 相似检索）
- MinIO（原文/报告/样例库）

**P2 · 微服务与治理全量**
- Nacos + OpenFeign + Gateway 路由 + Sentinel + Seata
- RocketMQ + 死信补偿 + XXL-JOB 分片
- Docker/K8s + Nginx + SkyWalking
- 数据集构建（人写/AI 各 1000 + 留出 200）与评测回归
